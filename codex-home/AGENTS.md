## Codex model routing (managed)

- 对编码、调试、代码评审、日志排查、迁移和架构规划，按需读取 Codex 配置目录内的 `skills/codex-workflow/SKILL.md`，按 `routing-controls.toml` 决策；用户不需要每次显式点名。
- 本段部署时应合并到已有全局指令，保留用户的其他约定。路径相对于目标 Codex 配置目录。
- T0/T1 根线程直接完成；T2 条件委派；T3/T4 要求独立执行上下文、验证后审查、单一写入者。
- 模型按语义能力与后果选择；推理档位按密集约束和不足证据选择。GPT-6 Luna 承担轻量工作，GPT-6.1 Sol 承担普通复杂工作，GPT-6 Astra 承担高后果或已证明的能力不足。
- 使用 `[execution_profiles]` 选择实际配置，`agents/*.toml` 是角色默认值；非默认档位需显式指定并核对运行时绑定，不能声称主聊天模型自动切换。
- 失败先区分资料、指令、工具、环境、容量、普通缺陷、推理投入不足与模型能力不足。只有有证据的后两类触发相应自动调整；专家仍有单独门槛。
- 同一验收范围最多两次自动配置转换、三次写入尝试；普通返工也计入总数，超过预算保留成果并交接。
- 高风险路由不得悄悄降低模型能力或省略独立审查；必要能力不可用则报告 route_blocked。
- 全局根模型默认来自 config.toml，但记录当前会话实际模型；自定义路由键只保留在 routing-controls.toml。
- 路由选择器是只读建议工具；由主代理检查模型可用性和权限后派发代理，记录真实执行证据。
